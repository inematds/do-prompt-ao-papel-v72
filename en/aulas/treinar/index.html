Lesson 6 · 16 min

Train in a cycle: five, ten rounds and a list

Once the agent can do the work, the part almost nobody does comes next: training. Don't ask just once. Ask five, ten times, evaluate it the way you'd evaluate an employee, gather the corrections into a list and run it in a cycle until it fixes everything. It takes more time and more usage, but in the end you have a written standard procedure that works for any agent.

  1. 1/6

    Run

    One good run can be luck; one bad run can be bad luck. Five to ten runs, with different inputs, show what the agent does every time and what it does only sometimes.

  2. 2/6

    Evaluate

    Look at all the results using the sheet's criteria and compare them with your example. Note for each run: "on task A I didn't like this, on B this was missing".

  3. 3/6

    List

    Put your notes together into a single list, with no repeats, from most serious to least serious. This is what you hand to the agent, not a pile of complaints.

  4. 4/6

    Fix

    Hand over the list, ask it to adjust, and run again. Cross off what passed, keep what failed. Repeat until the list is empty in every run.

  5. 5/6

    Standard

    With the list empty, ask the agent to write the standard procedure (a simple text): the steps, the rules that came out of the corrections, and the final test. It holds for the coming years and for any agent.

  6. 6/6

    The whole training

    Run several times, evaluate, list, fix in a cycle until it is empty, and write the procedure. The same mistake doesn't come back.

In my case (Nei, from INEMA), a good part of the day works like this: I delegate, I give feedback, and each correction becomes a written rule. In a way, I train the agent as much as it trains me.

02 · Five training habits

Tap or click each one.

1. In the chat

Each run in a new conversation of the same project: that way one run doesn't contaminate the other.

The list of corrections goes into the project instructions before the next run. A new conversation without the list in the instructions forgets everything.

In the terminalPut the list in AGENTS.md (or in a file it points to), and make each round a new session.

2. Varied inputs

Use different cases in each round: an easy one, a hard one, a weird one.

Running the same case five times only measures luck.

ExampleA notice about a party, a schedule change and a bus strike.

3. Grade everything

Also write down what turned out well: that is what goes into the procedure as "do it this way."

Without what worked, the list becomes just a list of bans.

NoteRound 3: great opening, keep it. Missing the start date.

4. One fix per line

Each line on the list says what to change in a way you can check.

"It felt off" doesn't help; "the date comes in the first sentence" does.

Good lineThe start date appears in the first sentence.

5. New model

When a new model comes out, your employee gets smarter for free. Keep the list of tasks it does every time.

Run the procedure on the new model, compare quality and cost, and decide with the results in hand.

TestThe same 5 inputs, on the current model and the new one, side by side.

The list reached zero in all 5 rounds. Write the standard procedure for this task (a plain text that I will keep) with:
- when to use it and what it delivers;
- the steps, in order;
- the rules that came from the fixes (one per line);
- the final test: how to check against the Measure before delivering.
Use language that another agent, or another person, can understand without asking me.
Simulation: illustrative example
  1. The start date appears in the first sentence. (failed in 3 of 5)
  2. No student names, not even in examples. (failed in 1 of 5)
  3. The text fits on one phone screen. (failed in 2 of 5)

After the cycle: 5 of 5 on every item.

  • One round and done: an error that shows up 1 time in 5 stays hidden until the day it matters.
  • A fix left loose in the chat: it disappears in the next conversation. It goes on the list and then into the procedure.
  • A procedure you write before the cycle: it comes from what the rounds showed, not from what you imagined.

04 · Practice: train your agent

Use the sheet from lesson 4 and the goal from lesson 5.

E1 · Five rounds

40 min

Run the task from your sheet five times, each in a new project conversation and with a different input, and fill in the evaluation (document or spreadsheet).

Done when: the table has five filled-in rows, with "yes" or "no" in the Measure column.

E2 · The list of fixes

15 min

Gather what to fix into a single list, one checkable fix per line.

Done when: the list has at least three fixes, and each one can be checked by looking at the result.

E3 · The cycle until zero

40 min

Paste the list into the project instructions, run the same inputs again (new chats), and repeat until they all pass.

Done when: in one final round, all five inputs passed every item on the list.

E4 · The procedure

15 min

Ask for the standard procedure and keep it with the sheet (in the chat, in the instructions or as a project file; in the terminal, in the folder).

Done when: the file exists and has the rules that came out of the corrections and the final test.
